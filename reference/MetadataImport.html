MetadataImport

The metadata for a single dataset.

Usage

Source

MetadataImport(
    source_format,
    source_path=None,
    source_version=None,
    dataset_name=None,
    dataset_label=None,
    dataset_description=None,
    creation_date=None,
    study_id=None,
    domain=None,
    variables=list(),
    codelists=dict(),
    missing_value_codes=dict(),
)

A MetadataImport is what import_metadata() returns for a file that describes one dataset. It holds the dataset-level information (name, label, study and domain), a VariableMetadata for each variable, the codelists that the variables use, and any declared missing-value codes, all in the same form whatever the format of the file.

The methods turn the metadata into things Pointblank can use: to_validate() builds a validation plan from the declared types and constraints, to_schema() gives a Schema of the column types, and missing_specs() builds MissingSpec objects from the missing-value codes. Variables and codelists can be looked up with get_variable() and get_codelist(), and summary() describes the whole dataset in text.

A MetadataImport can also be created directly, which is a way to write down the rules for a dataset that doesn’t come with a metadata file and still use the methods above. Calling len() on it gives the number of variables.

Parameters

source_format: str

The format the metadata was read from, such as "frictionless", "cdisc_define" or "spss". Any string can be used for metadata created directly.

source_path: str | None = None

The path of the file that was read. The default is None.

source_version: str | None = None

The version of the format or standard, such as "Define-XML 2.0". The default is None.

dataset_name: str | None = None

The name of the dataset, such as "DM". The default is None.

dataset_label: str | None = None

A human-readable label for the dataset, such as "Demographics". The default is None.

dataset_description: str | None = None

A longer description of the dataset. The default is None.

creation_date: str | None = None

When the metadata was created, as given in the file. The default is None.

study_id: str | None = None

The study identifier, for clinical data. The default is None.

domain: str | None = None

The CDISC domain, such as "DM" or "AE". The default is None.

variables: list[VariableMetadata] = list()

The metadata of each variable, as a list of VariableMetadata objects. The default is an empty list.

codelists: dict[str, Codelist] = dict()

The codelists used by the variables, as a dictionary from codelist name to Codelist. The default is an empty dictionary.

missing_value_codes: dict[str, list[MissingValueCode]] = dict()
The declared missing-value codes, as a dictionary from column name to a list of MissingValueCode objects. The default is an empty dictionary.

Examples

Let’s import the bundled Frictionless Table Schema, which describes a table of sensor readings:

import pointblank as pb

meta = pb.import_metadata(pb.load_metadata_example("table_schema.json"))

print(len(meta))
print(meta.variable_names)
print(list(meta.codelists))
6
['sensor_id', 'reading_time', 'temperature', 'pressure_hpa', 'battery_pct', 'status']
['status_enum']

The schema describes six variables, and the allowed values of status were read into a codelist named "status_enum". Metadata can also be written down directly, here for a small survey table:

survey = pb.MetadataImport(
    source_format="custom",
    dataset_name="survey",
    dataset_label="Household survey",
    variables=[
        pb.VariableMetadata(name="respondent_id", dtype="String", required=True, unique=True),
        pb.VariableMetadata(name="age", dtype="Int64", required=True, min_val=18, max_val=99),
    ],
)

survey
MetadataImport(source_format='custom', variables=2, codelists=0)

Either way, the result can be turned into a validation plan with to_validate(), which has an example of checking a table against its metadata.

to_validate()

Build a validation plan for a table from the metadata.

Usage

Source

to_validate(
    data,
    **kwargs,
)

This turns the declared types and constraints into validation steps, so that a table can be checked against its own documentation. The first step is a col_schema_match() with the schema from to_schema(). Then, for each variable in turn:

  • col_vals_not_null() if it’s required
  • rows_distinct() on the column if it’s unique
  • col_vals_between() if it has both min_val and max_val, or col_vals_ge() or col_vals_le() if it has only one of them
  • col_vals_in_set() if it has allowed_values
  • col_vals_regex() if it has a pattern
  • col_vals_not_in_set() with its missing_values, if it’s a string variable that declares some

The last step checks that the declared missing-value markers don’t appear in the data, as when a file was read without converting markers like "NA" to nulls. The min_length and max_length of a variable aren’t checked. None of the steps pass null values, so a null in an optional variable fails its range, set and pattern checks. To change any of the steps, get the plan as code with to_code() and edit it.

Parameters

data: Any

The table to validate.

**kwargs: Any
Arguments for Validate, such as tbl_name=, thresholds= or actions=. A label= replaces the default label, which is "Validation: <dataset name> (<format>)", or "Validation from <format> metadata" if the metadata has no dataset name.

Returns

Validate
A Validate object with the steps added. It hasn’t been interrogated yet.

to_schema()

Get a Schema of the variables’ names and types.

Usage

Source

to_schema()

The schema has a column for each variable, in order, with the variable’s dtype (or "String" if the dtype isn’t known). It can be used with col_schema_match() to check that a table has the expected columns and types. Only the names and types are included: constraints such as ranges and allowed values aren’t part of a schema, and are checked by the steps that to_validate() adds after its schema check.

Returns

Schema
A Schema with one column per variable.

Examples

import pointblank as pb

meta = pb.import_metadata(pb.load_metadata_example("datapackage.json"))

meta.to_schema()
Schema(columns=[('transaction_id', 'String'), ('customer_id', 'String'), ('amount', 'Float64'), ('quantity', 'Int64'), ('category', 'String'), ('sale_date', 'Date'), ('discount_pct', 'Float64'), ('email', 'String')])

The schema lists the eight columns of the transactions table with their types. The dtype names are those of Polars, so a schema check against a table from another backend fails on the type names (pandas, for example, has object and int64 where Polars has String and Int64). Convert such a table to Polars before checking it.

missing_specs()

Build a MissingSpec for each variable with missing values.

Usage

Source

missing_specs()

Each variable that declares missing values (such as the user-defined missing values of an SPSS variable, or the missing-value markers of a Frictionless schema) gets a spec made by its to_missing_spec() method. The dictionary can be given to missing_vals_tbl() as its missing=, and a single spec from it can be given to the missing= parameter of a validation method such as col_vals_regex().

The specs keep the values as they were declared. Frictionless and CSVW markers are strings (like "NA") and are declared for every field, but in a table read with typed columns they can only appear in the string columns. Keep only the specs of those columns before using them, since a string marker can’t be compared with a numeric or date column.

Returns

dict[str, MissingSpec]
A dictionary from column name to MissingSpec. Variables that don’t declare missing values aren’t included.

Examples

The bundled Frictionless Data Package declares "NA" and "N/A" as missing-value markers, so every one of its variables gets a spec:

import pointblank as pb

meta = pb.import_metadata(pb.load_metadata_example("datapackage.json"))
specs = meta.missing_specs()

print(list(specs))
print(specs["customer_id"].reasons)
['transaction_id', 'customer_id', 'amount', 'quantity', 'category', 'sale_date', 'discount_pct', 'email']
{'NA': 'missing_na', 'N/A': 'missing_n_a'}

The reasons were made from the markers, as no labels were declared for them. Let’s keep the specs of the string columns and use one of them in a validation step:

import polars as pl

string_specs = {
    name: spec for name, spec in specs.items() if meta.get_variable(name).dtype == "String"
}

tbl = pl.DataFrame({"customer_id": ["CUST-101", "N/A", "CUST-103", "NA"]})

(
    pb.Validate(data=tbl)
    .col_vals_regex(columns="customer_id", pattern="^CUST-[0-9]+$")
    .col_vals_regex(
        columns="customer_id", pattern="^CUST-[0-9]+$", missing=string_specs["customer_id"]
    )
    .interrogate()
)

summary()

Get a text summary of the metadata.

Usage

Source

summary()

The summary gives the format, the source file, the dataset name, label and domain (when known), and the numbers of variables and codelists. It then lists each variable with its dtype, its label, and its constraints: required, unique, the range, the number of allowed values, and the codelist. Printing a MetadataImport with print() shows the same summary.

Returns

str
The summary, as a string with one line per item.

Examples

import pointblank as pb
